# 09
Для передачи маленьких данных используется встроенный механизм Xcom. Обращаясь к объекту task, записываем в одну из баз метаданных airflow значение value, чтобы передать его из одной таски другой.
В этом примере получаетелем будет функция-фильтр, которая в зависимости от прочитанного из Xcom значения возращает определённое имя следующей таски. BranchPythonOperator, который получит эту функцию-фильтр, будет передавать управление таске, имя которой вернула функция-фильтр.

# 16
Написан кастомный хук и оператор. 
В операторе присутствует обязательный метод execute, который вызывается airflow, когда таск запускается на исполнение.

Хук - объект, осуществляющий взаимодействие с другими системами, api, базами данных. Он инкапсулирует логику подключения и даёт пользователю готовые методы. Часто читает параметры подключения из Connection, устанавливает соединение нужным драйвером.

# 17
`ClickHouseTransferHook` Наследуется от `ClickHouseHook`
`ClickHouseTransferOperator` наследуется от `ClickHouseOperator`
В файле `_v1` наследование реализовано неправильно и излишле. Потому что в методах кастомного хука всё равно создаётся родительский класс и вызываются его методы. Хотя хук же наследует всю эту логику, поэтому может выполнить её сам.

Переписанная версия с правильным полиморфизмом в файле `_v2`.
Теперь при создании `ClickHouseTransferHook` передаём туда conn_id, отрабатывает инициализатор базового класса. В методе `insert_df_to_db` используем метод execute, унаследованный также от базового `ClickHouseHook`.
